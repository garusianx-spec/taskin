# @taskin/api

The Taskin backend: a NestJS 12 modular monolith (ESM, strict TypeScript) on PostgreSQL 18,
Redis 7.4 and S3-compatible object storage. It implements RFC 0001
([docs/rfc/0001-backend-architecture.md](../../docs/rfc/0001-backend-architecture.md)); this
package currently covers **milestone M1**: the platform, authentication, workspaces and RBAC.

## Running it

```bash
npm run infra:up                                   # from the repo root: Postgres, PgBouncer, Redis ×2, S3, Mailpit
cp apps/api/.env.example apps/api/.env              # then: set -a; . apps/api/.env; set +a
npm run db:migrate -w @taskin/api                   # migrations + seeds, as taskin_migrator
npm run dev -w @taskin/api                          # http://localhost:4000, recompiles and restarts on change
```

Or run everything in containers with `npm run infra:app` (builds `apps/api/Dockerfile`, runs the
`migrate` job, then the API on :4000). Mailpit's inbox is at http://localhost:8025; with
`SMS_PROVIDERS=console` sign-in codes and invitation texts are logged instead of sent.

Routes live under `/api/v1`; `/health/live` and `/health/ready` sit outside it. The full contract
is [openapi.json](openapi.json), regenerated by `npm run openapi -w @taskin/api` and checked in CI.
Errors are RFC 9457 `application/problem+json` with a machine-readable `code`
(`ApiErrorCode` in `@taskin/contracts`) and the `requestId`.

## Runtime roles

One image, chosen by `APP_ROLE` (RFC §1.3):

| Role | Runs |
| --- | --- |
| `http` | The REST API: guards, validation, idempotency, rate limits |
| `worker` | BullMQ consumers (SMS, email), maintenance schedules (audit partitions, workspace purge, cleanup) and the outbox relay |
| `ws` | Health endpoints only for now; the Socket.IO gateway arrives with M3 |
| `all` | Everything, for local development |

Controllers are only mounted in the `http` composition, so a worker can never expose a route
without the authentication guard in front of it.

## How the pieces fit

- **Tenancy is enforced by the database.** Every tenant table has `FORCE ROW LEVEL SECURITY`
  keyed on `app.current_workspace_id()`, which `UnitOfWork` sets per transaction with
  `set_config(…, true)` (safe under PgBouncer transaction pooling). No setting, no rows.
  Children reference parents by `(workspace_id, id)`, so a cross-tenant reference cannot exist.
  The API connects as `taskin_app` (no `BYPASSRLS`); migrations run as `taskin_migrator`.
- **One use case, one transaction.** `UnitOfWork.run` retries serialization failures and
  deadlocks, and runs after-commit effects (cache invalidation) only after a successful commit.
  Nothing talks to the network inside a transaction; side effects go through the outbox.
- **Outbox.** Domain events are rows written in the same transaction; a trigger `NOTIFY`s the
  relay, which holds a session advisory lock on a direct connection (one leader cluster-wide),
  publishes BullMQ jobs with ids derived from the event id (at-least-once, deduplicated) and
  stamps `published_at`. Secrets that must travel (invitation links) are sealed with
  `APP_ENCRYPTION_KEY` until the worker sends them.
- **Authentication** is phone-first: OTP (HMAC-hashed, 5 attempts, per-number and per-IP limits
  that fail closed), then a session with a 15-minute EdDSA access token (no workspace claims)
  and a rotating refresh token in an HttpOnly cookie. Reusing a rotated-out refresh token
  revokes the session. Owners and admins hold an argon2id password used only as a step-up factor.
- **Authorisation** resolves the caller's membership per request from a Redis cache keyed by the
  workspace's `rbac_version` (bumped in the same transaction as any role or membership change,
  so demotions bite on the next request) and builds a CASL ability from the matrix. Rank and
  no-escalation rules are enforced in the use cases; the owner row is also protected by a trigger.
- **Correlation.** Every log line, audit row, outbox header and queue job carries the request id
  and W3C trace id.

## Tests

| Command | What | Needs |
| --- | --- | --- |
| `npm test -w @taskin/api` | Unit tests: the full 5 × 5 × 5 permission matrix, crypto, redaction, error mapping, SMS failover | nothing |
| `npm run test:int -w @taskin/api` | Integration suites: RLS isolation, auth, RBAC, idempotency, workspaces, invitations, audit coverage and correlation, query budgets | `npm run infra:up` |

The integration run migrates a template database from zero once; every test file clones it
(`CREATE DATABASE … TEMPLATE`) and uses its own Redis prefix, so files run in parallel. Override
the services with `TEST_DATABASE_ADMIN_URL`, `TEST_REDIS_URL` and `TEST_S3_*`.

`npm run db:snapshot -w @taskin/api` (with `DATABASE_MIGRATOR_URL`) rewrites
`db/schema.snapshot.txt` after a schema change; review the diff with the migration.

## Configuration

Every variable is listed, with its default and meaning, in [src/config/env.ts](src/config/env.ts);
[.env.example](.env.example) is a working local set. In production the process refuses to start
with the console SMS driver, without `JWT_PRIVATE_JWKS`, or with `COOKIE_SECURE=false`.
